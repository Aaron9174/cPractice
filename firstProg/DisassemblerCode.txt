=> 0x0804918c <+38>:    sub    esp,0xc

> Subtract 0xC from esp pointer
> ESP register has 0xffffc990 - 0xc => 0xffffc984
> Stack pointer (esp) now points to 0xffffc984
> Allocates 0xc (12 bytes) of data on the stack
> It does this because of System V i386 ABI memory alignment
  > When the call is executed further down, we must be at a 16-byte alignment
  > This leaves the stack pointer at 0xffffc984 which is 4 bytes shy of 16-byte alignment (always ends in 0)
    > 16 in decimal is 0x10 in hex
  > So then, when the push happens next, this subtracts another 4 bytes for the memory address stored in eax
  > This leaves us at a 16-byte alignment
